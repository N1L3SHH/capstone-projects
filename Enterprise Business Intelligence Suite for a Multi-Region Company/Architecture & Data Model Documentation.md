##### **Architecture \& Data Model Documentation****Schema Design**: Constellation Schema (Multi-Fact)**Central Fact Tables**: FactInternetSales \& FactResellerSales ($109.8M Combined Revenue Base)**Dimension Tables**: DimDate, DimProduct, DimGeography, DimCustomer, DimEmployee###### **Relationship Mapping:*** DimDate \[DateKey] -> (1:Many) -> FactInternetSales \& FactResellerSales \[OrderDateKey]* DimProduct \[ProductKey] -> (1:Many) -> FactInternetSales \& FactResellerSales \[ProductKey]* DimGeography \[GeographyKey] -> (1:Many) -> FactInternetSales \& FactResellerSales \[GeographyKey]* DimCustomer \[CustomerKey] -> (1:Many) -> FactInternetSales \[CustomerKey]* DimEmployee \[EmployeeKey] -> (1:Many) -> FactResellerSales \[EmployeeKey]###### **Data Cleaning \& Power Query:*** Imported the raw tables from the AdventureWorks database.* The main fix was in the DimGeography table. I had to filter out several orphaned "NA" territory records. If left in, these empty rows would have broken the gross margin aggregations and caused cross-filtering errors.* Formatted all cost and pricing columns to fixed decimals before loading them into the DAX engine to ensure accurate calculations.* Created a dedicated KeyMeasures table to organize all DAX calculations cleanly.
